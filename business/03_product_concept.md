# 03. プロダクト構想 — 赤ちゃん睡眠アプリ「すやすや」（仮称）

> 仮称: **すやすや**（候補: ねんねのよりそい / あんしんナイト / よりそいねんね）
> 名前は「監視・予防」を連想させない、安らぎ系の語で最終決定する。

## 3.1 一行コンセプト
**「赤ちゃんの夜が怖いママへ。正しい知識と、やさしい安らぎで、安心して眠れる夜を。」**

## 3.2 提供するもの / 提供しないもの（最重要の線引き）

| ✅ 提供する | ❌ 提供しない（絶対に） |
|---|---|
| 安全な睡眠習慣の知識（監修・出典つき） | SIDSの「予防」「防止」を謳うこと |
| 寝室環境のセルフチェック（仰向け・寝具など） | 赤ちゃんの呼吸/心拍の「監視」「検知」 |
| 寝かしつけの穏やかな体験（音・ルーティン） | 「これがあれば安心（＝危険がなくなる）」という断定 |
| 不安を受けとめるやさしい対話・安心の言語化 | 医療診断・受診要否の最終判断 |
| 受診の目安と、医療機関への橋渡し | 医療機器・医療行為 |

> 私たちは**医療機器ではない**。詳細は [04_safety_ethics](04_safety_ethics.md)。

## 3.3 コア機能（MVP候補）

### A. 安心ナイトルーティン
- 寝かしつけ前の数分間の流れ（やさしい音・暗さ・声かけ例）
- ホワイトノイズ／胎内音／子守唄。タイマーで自然にフェードアウト

### B. 安全な睡眠 セルフチェック
- 「仰向けで寝かせた」「寝具はかためで顔まわりに物がない」「適温」「禁煙環境」等を
  チェック → **できている所を肯定し、安心を返す**（減点ではなく加点の体験）
- 各項目に監修・出典リンク（厚労省/日本小児科学会/AAP）

### C. 夜のよりそいトーク（やさしいAI対話）
- 「息してるか不安で眠れない」等に、**まず気持ちを受けとめ**、正しい知識でそっと安心を渡す
- 緊急性が疑われるワードには、**ためらわず受診/救急を促す**安全フロー（[04](04_safety_ethics.md)）

### D. 安心メモ（記録だが、目的は安心）
- 寝た時間/起きた回数などを軽く記録。**評価しない**。「昨日もよく頑張ったね」を返す

### E. 学びの小部屋
- 既存コンテンツ・エンジンの監修記事/動画を、不安テーマ別にやさしく届ける

## 3.4 体験の原則（UX）
- **夜・片手・暗い部屋**で使える前提（大きなタップ領域、低照度UI、無音操作可）
- 通知は最小限。**不安を煽る通知をしない**（「危険」「確認して」等の表現は禁止）
- 言葉づかいは「指導」ではなく「寄り添い」。ママを主語に、肯定から入る
- カラー: 既存設定の安らぎ系（`config/settings.yaml`: primary `#4FB3D9` / secondary `#F4F9FC`）

## 3.5 技術構成（たたき台）
- **クライアント**: モバイル優先（将来 React Native / Flutter を想定）。
  検証初期は LP＋Web プロトタイプでも可
- **対話・コンテンツ生成**: Claude API（既存 `src/utils/claude_client.py` の方針を踏襲）
- **安全フィルタ**: 緊急ワード検出・受診誘導・免責の自動挿入（既存の監修ロジックを応用）
- **コンテンツ供給**: 既存 `main.py` パイプラインが学びの小部屋／集客記事を供給
- **データ**: 機微情報（赤ちゃんの健康）を扱うため、最小収集・暗号化・明確な同意を前提

## 3.6 MVPで検証したい問い
1. ナイトルーティン＋セルフチェック＋よりそいトークで、ママの「夜の不安」は実際に下がるか？
2. ママは「監視デバイスがない安心アプリ」に価値を感じ、継続・課金するか？
3. 安全な表現を保ったまま、検索/SNSから信頼ベースで集客できるか？

## 3.7 スコープ外（当面やらない）
- ハードウェア／呼吸・心拍センサー連携（思想に反する）
- 医療相談の代替・オンライン診療
- 多言語展開（まず日本のママに集中）
