# PSA鑑定 収支管理シート(売り切り型デジタル商品)

トレカを米国PSAに鑑定に出して売る個人向けの、Excel / Googleスプレッドシート用の収支管理シート。
BOOTH や note など、決済と配布を代行する場所に置いて売る前提(運営者は購入者とやりとりしない)。

| ファイル | 役割 |
|---|---|
| `build.py` | openpyxl で `dist/psa-shushi-kanri.xlsx` を生成する |
| `verify.py` | 生成物の検証(静的点検・手計算との突き合わせ・LibreOffice での再計算・無料ツールの計算結果との突き合わせ) |
| `dist/psa-shushi-kanri.xlsx` | シート本体(生成物)。zip に入れて配る |
| `listing.md` | 販売ページ用の文章の下書き(画像の並び順と説明文、購入前の確認事項、FAQ の置き方を含む) |
| `FAQ.md` | 購入者向けのよくある質問(18問)。zip にはテキスト版を入れる |
| `make_zip.py` | 配布用の `dist/psa-shushi-kanri-v1.0.zip` を作る |
| `dist/psa-shushi-kanri-v1.0.zip` | 販売サイトに登録するファイル(生成物)。xlsx・`よくある質問_FAQ.txt`・`はじめにお読みください.txt` |
| `images_src/` | 商品画像の元になる HTML(`01`〜`05`)・共通の `style.css`・撮影スクリプト `shoot.js` |
| `dist/images/` | 商品画像 5枚(生成物) |

## 再生成の手順

```sh
pip install openpyxl                      # 未導入なら(確認済み: openpyxl 3.1.5)
python3 products/psa-sheet/build.py       # dist/psa-shushi-kanri.xlsx を作る
python3 products/psa-sheet/verify.py      # 検証(NG があれば終了コード 1)
```

## 販売物ひとそろいを作り直す手順(v1.0)

リポジトリのルートで、この順に実行する。

```sh
python3 products/psa-sheet/build.py            # 1. xlsx
python3 products/psa-sheet/verify.py           # 2. 検証。「NG 0」を確認
python3 products/psa-sheet/make_zip.py         # 3. 配布用 zip(xlsx + FAQ のテキスト版 + はじめにお読みください)
node products/psa-sheet/images_src/shoot.js    # 4. 商品画像 5枚 → dist/images/
```

- 3 は `FAQ.md` から記号を落としたテキストを作って zip に入れる。テキストは UTF-8(BOM 付き)・CRLF。zip 内の時刻は固定で、何度作っても同じバイト列になる。実行すると中身の一覧が出るので、3ファイルあること・日本語名が読めることを見る。
- 4 は Playwright(chromium)と日本語フォントが必要(作成時は IPAPGothic)。1200×900 の画面を deviceScaleFactor 2 で撮るので、PNG は 2400×1800 ピクセル。画面からはみ出した要素や切れたセルがあると「要確認」と出て終了コード 1 になる。フォントが違う環境では字幅が変わるので、作り直したら5枚とも目で見る。
- 画像の数字は HTML に直書き(xlsx からは読まない)。サンプルデータや初期値を変えたら `images_src/*.html` の数字も手で直す。
- バージョンを上げるとき: `build.py` の `RELEASE`、`make_zip.py` の `RELEASE_DATE`、`FAQ.md` と `listing.md` のバージョン表記、`images_src/01-cover.html` の「v1.0」を直す。
- xlsx・FAQ を直したら必ず 3 をやり直す(zip の中身は自動では追従しない)。

## 補足

- 何度実行しても同じバイト列のファイルになる(作成日時と zip 内の時刻を固定)。openpyxl のバージョンが変わると中身が変わることはある。
- `verify.py` は LibreOffice(`soffice`)があれば実際に再計算して値を比べる。無ければその部分は「未確認」と表示して飛ばす。
- 1枚あたり費用の式は `pokeca/core.py` の `per_card_costs` と同じ。`verify.py` が両者を突き合わせる(Python 側は読むだけ)。
- 初期値・サンプルデータ・文言を変えるときは `build.py` を直して再生成する。初期値やサンプルを変えたら `verify.py` の `HAND_*`(手計算の期待値)も直す。

## 販売までに運営者がやること

1. **実機での動作確認(必須・未実施)**: `dist/psa-shushi-kanri.xlsx` を
   - Microsoft Excel で開き、「編集を有効にする」を押したあと数値が表示されること、プルダウン・フィルタ・入力が動くこと
   - Googleスプレッドシートに「ファイル→インポート」で取り込み、同じ数値が出ること、プルダウンが残っていること

   を確かめる。見るべき値: 在庫台帳 5行目の利益 21,998 / 6行目 −3,002、月次集計の年間合計 売上 63,000・原価 44,004・利益 18,996、注文別集計 SAMPLE-001 の利益 18,996、シミュレーターの仕入れ上限 14,100(売却額に対する利益率の行)と 17,900(仕入れ値に対する利益率の行)。確認した環境を `listing.md` の「対応環境」に書く。
2. 販売サイトの登録(BOOTH / note など)と、そのサイトの規約(デジタル商品の返金・表示義務)の確認。特定商取引法にもとづく表記が必要かどうかも販売サイトの案内に従って確認する。
3. 価格の決定。`listing.md` の価格帯は調査にもとづかない仮置き。類似商品の価格を見てから決める。
4. 商品画像は `dist/images/` の5枚を `listing.md` の順で登録する(作成済み。実機のスクリーンショットではなく、サンプルと同じ値で組んだ見本画像)。販売サイトの画像サイズ・容量の上限は未確認なので、登録画面で確かめる。
5. `listing.md` の【 】を埋め、販売ページに貼る。配布ファイルは `dist/psa-shushi-kanri-v1.0.zip` を登録する。
6. 商品名に「PSA」を使ってよいかの判断。PSA は他社の名称・商標。`listing.md` とファイル内には「非公式」と明記してあるが、販売サイトの規約と合わせて運営者が判断する。
7. 設定シートの初期値(為替 155、鑑定料 79.99 USD など)は「一例」と明記してあるが、販売時点で大きくずれていれば `build.py` の `SETTINGS` を直して再生成する。

## シートの設計メモ

- 設定値は名前付き範囲(`cfg_fx` など9個 + `cfg_cost_per_card`)で他シートから参照。% の項目は「10」のように数値で入れ、数式側で ÷100 する(パーセント書式の入力ゆれを避けるため)。
- 在庫台帳は 1行=1枚。数式は自分の行だけを参照するので、並べ替え・フィルタ・行削除で壊れない。入力列 A〜J が全部空の行は "" を表示。
- 集計シートは在庫台帳の列全体(`在庫台帳!$O:$O` など)を参照するので、500行を超えて行を足しても集計から漏れない。
- 月次集計は `SUMIFS` に `">="&DATE(年,月,1)` と `"<"&DATE(年,月+1,1)` を渡して月を切る(TEXT や配列数式を使わない)。
- 番号の列(管理番号・番号・PSA注文番号・認定番号)は文字列書式。「001/100」が日付に化けたり先頭の0が落ちたりしないようにするため。
- 設定・注文別集計・月次集計・シミュレーターはパスワードなしでシート保護(入力セルだけロック解除)。在庫台帳は並べ替えのため保護していない。
- 台帳・月次集計・期待利益率は「利益 ÷ 売却額」。シミュレーターの仕入れ上限は、目標利益率の定義ごとに2行出す: B23「売却額に対する利益率」(台帳・月次と同じ定義。判定はこの行)と、B24「仕入れ値に対する利益率」(`pokeca/core.py` の `recommend`、無料ツール `products/tools-site/src/lib.js` の `psaMaxBuy` と同じ定義)。C列は切り下げ前の値。
- `verify.py` は、無料ツールの初期値を入れたときに B24 が `psaMaxBuy` の結果(19,800)と一致することを、lib.js を node で実行して確かめる(node が無ければ「未確認」)。シートは費用を1円に四捨五入し、販売手数料も引くので、手数料率が 0 でないときや100円の境目では一致しないことがある(FAQ の Q15)。ツール側の初期値・式を変えたら `verify.py` の `TOOL_*` も直す。

## 既知の制限

- **Excel と Googleスプレッドシートの実機では未検証**。検証は openpyxl での静的点検と LibreOffice Calc での再計算だけ。両方にある関数だけを使ってはいるが、取り込み後の見た目(列幅・色・フォント)、プルダウン、入力規則、シート保護、名前付き範囲がそのまま残るかは確かめていない。
- xlsx に計算済みの値は入っていない(開いたアプリが計算する)。Excel の保護ビューや、販売サイト・スマートフォンのプレビュー表示では数式の結果が空に見えることがある。
- 設定は1組だけ。為替や鑑定料を変えると過去の行の鑑定費用も変わる。過去ぶんを固定するには、その行の鑑定費用セルに実額を上書きする(「使い方」シートに記載)。注文ごと・サービスレベルごとの料金の持ち分けはできない。
- 鑑定費用は「状態が在庫かつ未鑑定(または空欄)なら 0、それ以外は1枚あたり費用」。鑑定済みで仕入れたカードは鑑定費用セルに 0 を上書きする必要がある。
- 送料・関税は「1箱の枚数」で均等割り。実際の箱ごとの枚数の違いは反映しない。
- 在庫台帳の数式は 500行、注文別集計は 30行まで(増やし方は「使い方」シートに記載、注文別は行を足せない)。
- 商品画像は HTML で組んだ見本で、Excel / Googleスプレッドシートの実際の画面ではない(色と値は xlsx に合わせてあるが、フォントや罫線の見え方は実物と違う)。
- zip の日本語ファイル名は UTF-8 フラグ付き。Python と unzip での展開は確認したが、Windows・Mac の標準の展開機能では確認していない。
- 黄色いセルの「切り取り→貼り付け」をすると数式の参照がずれる(表計算ソフトの仕様)。「使い方」シートで注意している。
- 売却日が文字列の行は月次集計に入らない(月次集計シートのチェック欄に件数が出る)。
- 相場の自動取得、複数通貨、消費税・所得税の計算、1行で複数枚の管理はしない。
- 税務・関税の正しさは検証していない。税率・関税の初期値は指示された一例で、制度の調査はしていない。
