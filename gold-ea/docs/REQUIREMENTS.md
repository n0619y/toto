# FX GOLD EA 要件定義書

最終更新: 2026-06-22 / バージョン: 0.1 (ドラフト)

---

## 0. この文書の位置づけ

本プロジェクトのゴールは **「資金が増えるEA（自動売買プログラム）を作成すること」**。
しかし「資金が増える」は曖昧なため、本書で **計測可能な指標（KPI）** に落とし込み、
そこへ到達するために **やるべきこと** を要件として定義する。

> ⚠️ 重要な前提：相場に「絶対に勝てるEA」は存在しません。
> 本プロジェクトの現実的な目標は「**統計的に優位性（エッジ）があり、
> 適切なリスク管理のもとで、長期的に期待値がプラスになるEAを作り、
> それをデータで検証すること**」です。一発の利益ではなく再現性を重視します。

| 項目 | 内容 |

## 2. ゴールの具体化（成功の定義）

「資金が増える」を以下の KPI で定義する。バックテスト＋フォワードテストで判定する。

| KPI | 目標値（初期案・調整可） | 意味 |
|-----|------------------------|------|
| プロフィットファクター (PF) | **≥ 1.3** | 総利益 ÷ 総損失。1.0超で黒字 |
| 最大ドローダウン (Max DD) | **≤ 20%** | 資金の最大下落率。生存性の指標 |
| リスクリワード比 (RR) | **≥ 1.0** | 平均利益 ÷ 平均損失 |
| 勝率 | 戦略に依存（RRとセットで評価） | 単独では評価しない |
| 期待値（1トレードあたり） | **> 0** | 必須条件 |
| 取引回数（検証期間内） | **≥ 100** | 統計的に有意なサンプル数 |
| シャープレシオ | **≥ 1.0**（参考） | リスク調整後リターン |

> これらの数値目標は仮置きです。あなたのリスク許容度・運用資金額に合わせて
> §10 のヒアリングで確定します。

## 3. 制約・前提条件

- **MT4 / MQL4** で動作すること（MT5ではない）。
- ゴールドは**スプレッドが広く・ボラティリティが高い**銘柄である点を前提に設計する。
- 業者ごとに **銘柄名・桁数・最小ロット・ストップレベル** が異なるため、汎用化する。
- スリッページ・約定拒否・スワップ（特にゴールドはマイナススワップが大きい）を考慮する。
- 実運用には **常時稼働環境（VPS）** が必要（PCを24時間つけっぱなしでも可）。
- バックテストには **高品質なヒストリカルデータ（できればティックデータ）** が必要。

## 4. 機能要件（EAが備えるべき機能）

### 4.1 エントリー（新規建て）
- [ ] 戦略ロジックに基づく買い／売りシグナル生成
- [ ] 時間フィルター（取引する時間帯／曜日の限定、例：ロンドン・NY時間）
- [ ] スプレッドフィルター（スプレッド拡大時はエントリーしない）
- [ ] 最大同時ポジション数の制限
- [ ] （任意）重要指標発表時の取引停止（ニュースフィルター）

### 4.2 エグジット（決済）
- [ ] ストップロス（SL）／テイクプロフィット（TP）の必須設定
- [ ] トレーリングストップ（任意）
- [ ] ブレイクイーブン（建値撤退、任意）
- [ ] 時間切れ決済（任意）

### 4.3 資金・リスク管理（最重要）
- [ ] **1トレードあたりのリスク％でロットを自動計算**（固定ロットではなく資金連動）
- [ ] 口座残高に対する最大許容ドローダウンでの取引停止（サーキットブレーカー）
- [ ] 1日あたりの最大損失額／回数の制限
- [ ] ロット上限・下限のガード

### 4.4 運用・保守
- [ ] パラメータはすべて `input` で外部化（最適化・調整可能に）
- [ ] チャート上に稼働状況・損益を表示（ダッシュボード）
- [ ] ログ出力（エントリー／決済理由、エラー）
- [ ] マジックナンバーで他EA・手動取引と区別

---

## 5. 非機能要件（品質）

- **堅牢性**: 接続断・再起動・約定エラー時もポジション整合性を保つ。
- **冪等性**: 同一ティックで重複エントリーしない。
- **可搬性**: 業者・銘柄名・桁数の違いを自動吸収する。
- **検証可能性**: ストラテジーテスターで再現性高くバックテストできる。
- **可読性／保守性**: 設定・ロジック・実行を分離した構成にする。

---

## 6. 戦略選定プロセス（戦略が未定のため）

戦略は「決め打ち」せず、**候補を作って検証 → 数字で選ぶ**。ゴールド向けの代表的候補：

| # | 戦略タイプ | 概要 | ゴールドとの相性 |
|---|-----------|------|----------------|
| A | トレンドフォロー | 移動平均・ブレイクアウトで順張り | ◎ トレンドが出やすい |
| B | ボラティリティブレイクアウト | ATR/レンジブレイクで初動を取る | ◎ 高ボラ |
| C | 平均回帰（逆張り） | RSI/ボリンジャー等で行き過ぎを取る | △ レンジ限定 |
| D | 時間帯ベース | 特定セッションの傾向を利用 | ○ |

→ まずは **A（トレンドフォロー）** を MVP として実装し、KPI を満たすか検証する方針を推奨。

## 8. 検証要件（ここが勝敗を分ける）

- [ ] **高品質データ**でのバックテスト（モデリング品質90%以上を目標）
- [ ] **複数期間**でテスト（上昇相場・下落相場・レンジを含む）
- [ ] **アウトオブサンプル検証**（最適化期間と検証期間を分ける）
- [ ] **フォワードテスト（デモ運用）** で実時間の挙動を確認
- [ ] スプレッド・スリッページを現実的な値に設定して評価
- [ ] **過剰最適化（カーブフィッティング）の回避** をレビュー

---

## 9. リスク・免責事項

- 自動売買は **元本を失うリスク** がある。検証なしのリアル運用は厳禁。
- 過去の成績は将来を保証しない。
- 必ず **デモ → 少額リアル** の順で段階的に運用する。
- 本EAは投資助言ではなく、あくまでツールである。

---

## 10. 確定が必要な項目（ヒアリング）

要件を最終化するため、以下を確認したい：

1. **運用資金額**（例：10万円 / 1,000ドル など）→ ロット計算・目標設定に直結
2. **リスク許容度**：1トレードで資金の何％までリスクを取れるか（推奨：0.5〜2%）
3. **目標リターン**：月利／年利の希望（現実的な範囲で）
4. **利用予定の業者**（銘柄名・スプレッド確認のため／未定でも可）
5. **バックテスト用データ**：手元にティックデータはあるか、用意が必要か
