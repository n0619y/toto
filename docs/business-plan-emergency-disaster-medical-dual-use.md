# 事業計画書

## 傷病者情報・衛生指揮統制プラットフォーム事業
### — 救急・災害・極限環境医療のデュアルユースSaaS —

- 作成日:2026年7月11日
- ステータス:ドラフト v0.1(シード資金調達・創業準備用)
- ※本計画書中の市場規模・数値は公開情報と一般的な相場観に基づく**仮置き値**であり、事業化検討の次ステップで一次情報による検証を行う前提のものです。
- **⚠ 検証結果の反映について:** 本計画は別途実施したディープリサーチ(`research-report-dual-use-medical-defense.md`)により以下の重要な修正が必要と判明している。**次版(v0.2)で下記を本文に反映すること。**
  1. **競合:** 消防向け救急搬送SaaSはTXP Medical(NSER mobile)が既に沖縄南部・山形県・仙台全市・東京消防庁で面展開しており、「空いたビーチヘッド」ではない。正面衝突を避け、有事・MCI・国民保護・後送オーケストレーション・通信途絶耐性・血液ロジで差別化する。
  2. **市場:** 国内防災情報システム市場は2,150億円(2024)・年率約1.5%の低成長で大半がレガシー無線。SaaS実TAMは大幅に薄い。物語を「防災DX全体」から「災害輸血+有事衛生+装備庁R&D」の複線へ張り替える。
  3. **推奨第一プロダクト:** 防衛衛生予算の最大塊は「自律的な血液供給」。競合薄・規制軽・政策予算ありの交点として**血液・戦傷医療資材のロジ/トレーサビリティ**を第一プロダクト、衛生指揮統制/後送を第二とするのが有利。
  4. **フェーズ3(米国):** 米DoD SBIRは51%以上の米国市民/永住者保有が必須で日本資本のまま直接応募不可。米国法人スキーム/現地提携/同盟国連接ルートへ要修正。T6 Health Systemsが本事業の直接の先行成功事例(参照かつ将来の提携/競合先)。

## 1. エグゼクティブサマリー

**事業内容:** 多数傷病者事案(MCI: Mass Casualty Incident)・災害・戦傷医療に共通する最大のボトルネックである「傷病者情報の収集・共有・指揮統制」を解決するSaaSプラットフォームを開発・提供する。

**コア市場:** 消防・DMAT・都道府県(災害医療)・災害拠点病院。**アンカー顧客としての拡張市場:** 自衛隊衛生科・国民保護・在外邦人保護。**長期市場:** 米国・NATOの軍事医療(Military Health)市場。

**なぜ今か:**
1. ウクライナ戦争の戦訓により「戦傷医療の最大の課題は医療技術ではなく情報とロジスティクス」であることが世界的に再認識された
2. 日本の防衛費増額(GDP比2%)の中で自衛隊の衛生機能・南西方面の後送体制が明確な投資テーマになっている
3. 防災DX・自治体システム標準化の政策的追い風により、災害医療分野の情報化予算が継続的に確保されている
4. K Program・安全保障技術研究推進制度・SBIRなど、デュアルユース技術への公的R&D資金が急拡大している

**戦略の骨子:** 「規制の軽いレイヤーから入り、金の重いレイヤーに登る」
- フェーズ1(0〜2年):薬機法非該当のソフトウェアで民間(消防・自治体・病院)売上を確立
- フェーズ2(2〜4年):公的R&D資金で防衛向け機能・ハード連携を開発、自衛隊調達へ
- フェーズ3(4年〜):国内実運用実績を信用材料に米国・NATO市場へ展開

**5年後の目標:** ARR 15億円、国内災害医療情報基盤のデファクト、自衛隊衛生への正式調達実績、米国市場参入。

**調達計画:** シードラウンド 1.5億円(本計画)→ シリーズA 6億円(Y2)→ シリーズB 20億円(Y4)。並行して公的R&D資金を累計5億円規模で獲得(ただし総資金の5割以内を規律とする)。

## 2. ビジョン・ミッション

- **ビジョン:** 「防ぎ得た死(Preventable Death)」を、平時・災害時・有事のすべてでゼロに近づける。
- **ミッション:** 極限環境における傷病者情報の断絶をなくし、最適な医療資源配分を実現するインフラを提供する。
- **ポジショニング上の原則:** 当社は「救急・災害・極限環境医療の会社」であり、防衛は重要な顧客セグメントの一つと位置づける。「防衛スタートアップ」と自己定義しない(採用・調達・共同研究上の戦略的判断)。

## 3. 解決する課題

### 3.1 現場の課題(民間)

多数傷病者事案(大規模事故、地震、テロ等)において:

1. **トリアージ情報が紙タグで管理され、リアルタイムに集約されない。** 現場・救護所・搬送先病院の間で傷病者の位置・重症度・搬送状況が見えない
2. **搬送先マッチングが電話ベース。** 病院の受入可否確認に時間を要し、特定病院への搬送集中(オーバートリアージ集中)が発生する
3. **既存の広域災害救急医療情報システム(EMIS)は病院の状況報告が中心**で、傷病者個々のトラッキングや現場指揮には対応していない
4. **訓練と実災害でツールが異なり、習熟が定着しない**

結果として、災害医学で言う「防ぎ得た災害死(Preventable Disaster Death)」が発生し続けている。

### 3.2 防衛の課題(アンカー顧客)

1. 南西方面有事を想定した場合、**多数戦傷者の洋上・島嶼からの後送**において傷病者情報の追跡・優先度管理・後送手段割当が最大のボトルネック
2. 自衛隊の衛生情報システムは部隊間・省庁間(海保・DMAT・災害拠点病院)の相互運用性が低い
3. 国民保護事態では**軍民の医療リソースを統合運用する情報基盤が存在しない**
4. 米軍(BATDOK等)は同種システムの実戦配備を進めており、日米共同作戦上の相互運用ギャップが顕在化しつつある

### 3.3 両市場に共通する本質

**「傷病者一人ひとりを、発生現場から確定的治療まで、途切れなくデジタルに追跡し、限られた医療資源(病床・後送手段・医療チーム)と動的にマッチングする」**という課題は民間災害医療と戦傷医療で完全に同型である。これが本事業のデュアルユース性の根拠であり、単一プロダクトで両市場に展開できる。

## 4. プロダクト

### 4.1 プロダクト構成

**「(仮称)TRIAGE LINK」— 傷病者情報・衛生指揮統制プラットフォーム**

| モジュール | 機能 | 主要ユーザー |
|---|---|---|
| ① 電子トリアージ | NFC/QRタグ+モバイルアプリによる傷病者登録・トリアージ記録・位置追跡 | 救急隊員・DMAT隊員・衛生科隊員 |
| ② 現場指揮ダッシュボード | 傷病者一覧・重症度分布・救護所/搬送状況の可視化 | 現場指揮所・保健所・災害対策本部 |
| ③ 搬送先マッチング | 病院受入キャパシティとの動的マッチング・搬送手段割当 | 指令センター・搬送調整本部 |
| ④ 訓練モード | 実災害と同一UIでの訓練シナリオ実行・事後検証(AAR) | 消防・DMAT・自衛隊の訓練部門 |
| ⑤ 連携API | EMIS・消防指令システム・電子カルテ・(将来)防衛系システムとの連携 | システム管理者 |

### 4.2 技術的差別化

1. **通信途絶耐性(オフラインファースト設計):** 災害・戦場に共通する要件。端末間メッシュ同期と遅延許容ネットワーク(DTN)設計により、通信インフラ喪失下でも運用継続。この要件は民間ITベンダーが最も作り込めていない部分であり、かつ防衛市場への最重要の技術ブリッジとなる
2. **「訓練=実運用」の同一システム設計:** 訓練での利用実績がそのまま実災害時の習熟に直結。訓練市場(毎年確実に予算がつく)を収益とデータ蓄積の両面で活用
3. **将来のAIトリアージ支援:** 蓄積データを基にした重症度予測・後送優先度支援。※薬機法上プログラム医療機器(SaMD)該当となる可能性があるため、フェーズ2以降に規制戦略と併せて段階投入

### 4.3 規制戦略(重要)

- フェーズ1のプロダクトは**「診断・治療の判断を行わない情報管理・伝達システム」として設計し、薬機法非該当を維持**する(該非判定の事前相談を実施)。これにより承認プロセスなしで市場投入可能
- AIによる重症度予測等の「診断支援」機能はクラスII SaMDとなる可能性が高く、収益基盤確立後のフェーズ2で承認取得に着手する
- 個人情報(要配慮個人情報)・自治体情報セキュリティ(LGWAN対応、ISMAP取得)への対応をアーキテクチャ初期段階から組み込む

### 5.2 市場の特性

- **予算の出所が「防災」「国土強靱化」「防衛」「地方創生」と複線的**であり、単一予算への依存リスクが低い
- 災害対応・国民保護は**政治的に削減しにくい予算領域**
- 一方で自治体・官公庁市場は**入札・年度予算の制約**があり、販売サイクルは6〜18ヶ月と長い。これを織り込んだ資金計画とする(→第9章)

### 5.3 競合分析

| 競合カテゴリ | 例 | 当社との差異 |
|---|---|---|
| 既存官公庁ベンダー(防災システム) | 大手SIer各社 | 総合防災システムの一部として扱い、傷病者個票レベルの追跡・現場UXが弱い。当社は現場特化・オフライン耐性で差別化 |
| 救急医療ICTスタートアップ | 救急搬送支援・ER業務支援系の国内各社 | 平時救急が中心でMCI・災害・防衛特化ではない。協業(データ連携)の可能性もある |
| 公的システム | EMIS | 病院状況報告が中心で傷病者トラッキング機能なし。競合ではなく連携対象 |
| 海外軍事医療IT | 米BATDOK、T6 Health Systems等 | 米軍中心で日本の消防・DMAT・自治体要件に非対応。国内市場では当社が先行可能。長期的には米国市場で競合 |
| 紙・ホワイトボード(現状維持) | — | 実質的な最大の競合。訓練モジュールによる「導入前から使い慣れる」戦略で置換する |

**参入障壁の構築:** ①現場運用ノウハウの暗黙知(「中の人」チーム)、②訓練データ・実災害データの蓄積、③自治体・防衛の調達実績と情報セキュリティ認証、④EMIS等公的システムとの連携ポジション。

## 7. Go-to-Market戦略

### フェーズ1(Y1〜Y2):民間ビーチヘッド確立

1. **初期顧客:** 政令市消防局2〜3、先進的な県1〜2、災害拠点病院5〜10でのPoC→有償化
2. **入口は「訓練」:** 実災害での採用判断は導入障壁が高いため、毎年必ず実施される総合防災訓練・国民保護訓練・DMAT技能維持研修への訓練モードの提供から入る。訓練での高評価→本運用契約、の導線を標準化する
3. **学会・キーオピニオンリーダー戦略:** 日本災害医学会・日本救急医学会での発表・共同研究を通じ、災害医療の中核人材(DMAT事務局経験者等)からの推奨を獲得する
4. **SBIR・防災関連補助金**を活用し、自治体側の導入コストを軽減する制度設計を提案営業に組み込む

### フェーズ2(Y2〜Y4):防衛アンカー顧客の獲得

1. 防衛装備庁「安全保障技術研究推進制度」またはK Programへの応募により、**通信途絶環境・大量後送シナリオ向けの機能拡張を公的資金で開発**
2. 自衛隊衛生科・防衛医大との共同研究→統合演習(自衛隊統合防災演習、日米共同演習の衛生訓練等)での試験運用→部隊使用の実績化
3. 国民保護共同訓練(国・県・自衛隊・消防合同)は**軍民両市場に同時にリーチできる最重要のショーケース**として最優先で押さえる
4. この段階でセキュリティクリアランス(適性評価)対応・情報管理体制を整備する

### フェーズ3(Y4〜):米国・NATO展開

1. 米国法人設立、現地アドバイザー(退役軍医官等)の招聘
2. DHA・SOCOM(調達が速く医療ITに積極的)向けのSBIR(米)・OTA契約を入口とする
3. 「日本の消防・DMAT・自衛隊での実運用実績」を信用材料に、同盟国相互運用性(日米衛生連携)を訴求点とする
4. 並行して、人道支援・災害救援(HA/DR)文脈での国際機関・NGO市場も探索する

## 11. リスクと対応策

| リスク | 影響 | 対応策 |
|---|---|---|
| 官公庁の販売サイクル長期化による資金枯渇 | 高 | 訓練サービスによる早期売上化、ランウェイ24ヶ月以上を常時維持、マイルストーン型の調達設計 |
| 防衛予算の政策転換(政権交代・国際情勢変化) | 中 | 民間売上のみで存続可能な損益構造を維持(防衛比率は売上の50%を上限目安とする) |
| 大手SIerの参入 | 中 | 現場ノウハウ・オフライン技術・訓練データの先行蓄積。SIerとは競合ではなく販売パートナー化を優先交渉 |
| 医療界・アカデミアの防衛忌避による協力難 | 中 | 「災害医療の会社」としてのポジショニング徹底、人道目的(HA/DR)の実績を先行して蓄積 |
| SaMD規制強化によるAI機能の投入遅延 | 低〜中 | 非該当機能のみで成立する事業構造を維持、規制対応は専任者を早期採用 |
| 情報セキュリティ事故 | 高 | 要配慮個人情報を扱う前提でのセキュリティ・バイ・デザイン、第三者監査、サイバー保険 |
| キーパーソン(CMO・防衛渉外)の離脱 | 高 | 創業株式・SOによるリテンション、顧問ネットワークによる冗長化 |

## 12. Exit戦略・長期構想
